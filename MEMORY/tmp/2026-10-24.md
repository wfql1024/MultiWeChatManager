## 02:05:33 — 补充：E:\Now 桌面也不可写；结论是「按进程映像过滤」而非路径/ACL

- 做了什么 / 结论：普通权限任务里跑纯 Java 探针：`E:/Now`、`E:/Now/Inbox`、`E:/Now/Desktop`、`%APPDATA%`、`%LOCALAPPDATA%` 全部 `AccessDeniedException`；**同一个会话同一个令牌**里 `cmd mkdir %APPDATA%\...` = OK、`node.exe` 写 `%APPDATA%` = OK。→ 排除 ACL/权限/完整性标签（它们无法按“谁在写”区分），指向按进程映像过滤的安全软件（本机 联想电脑管家/Huorong，`wsctrl11.exe`）。
- 为什么 / 证据：`whoami /groups` 在该任务里 = Medium（S-1-16-8192）；`icacls E:\Now` 有 `Authenticated Users:(M)`、`E:\Now` 还带一条 `GuestUser:(OI)(CI)(N)`(deny)；而 `tmp\probe` 的 ACL 里有 DSH 沙箱留下的 `S-1-4-…:(W,D,DC)` 与 `Everyone:(DENY)(DC)` —— **说明我的测试环境本身被 DSH 沙箱改过 ACL，E: 盘的结论不能当“干净机器”结论**，但“cmd/node 能写、JVM 不能写”这一组对照仍然成立。
- 候选去向：lessons（ACL 不能按映像区分 → 只有安全软件能造出这种差异；DSH 沙箱会改 ACL，探针结论要在纯用户环境复核）、decisions（是否做“数据目录候选链 + 自动降级 + 诊断”，待用户拍板）

## 02:31:42 — 决策落地：打包版默认以管理员身份运行（AdminBoot）

- 做了什么 / 结论：新增 `com.jfmultichat.boot.AdminBoot`（**刻意不用 JNA**，全走 whoami / reg / powershell / mshta 系统命令），在 `Launcher.main` 最前面调用 `ensureElevated(args)`：已提权 → 顺手把 `HKCU\…\AppCompatFlags\Layers` 写成 `~ RUNASADMIN`（以后双击直接提权）；未提权且是打包启动器 → `powershell Start-Process -Verb RunAs` 重启自身后退出；用户取消 UAC → mshta 弹提示并退出。`--dev`/非 jar 运行**不提权**，gradle run 不受影响。
- 为什么 / 证据：用户 2026-10-24 定「一刀切管理员」，且实测普通令牌下连写 HKCU 都被拒（`reg add` exit=1 拒绝访问）、JNA 连解压 `jnidispatch.dll` 到 %TEMP% 都失败（`UnsatisfiedLinkError: 拒绝访问`）——所以检测/提权/登记全程不能依赖 JNA，也必须**先提权再登记**（普通令牌写注册表同样被拦）。验证：`AdminProbe` 管理员下 `isElevated=true`、`markRunAsAdmin=true`、`readFlag=~ RUNASADMIN`；LIMITED 任务下 `isElevated=false`、`raw powershell` 可执行（提权通道可用）、`reg add` 被拒。重打包后冒烟启动 → `数据目录可写: …UserFiles -> true`。
- 已知副作用（要写进用户文档）：每次启动一次 UAC；提权后**从非提权资源管理器拖文件进窗口会被 UIPI 拦**（改用「浏览」按钮选文件）；jpackage 17 不支持自定义 manifest（实测 `--resource-dir` 传 main.win.manifest 无效、无 mt.exe），所以走注册表兼容层。
- 候选去向：facts（启动期提权链路 + 兼容性层键值）、lessons（普通令牌下 JNA/注册表都会被安全软件拦；提权登记必须放在提权之后）、decisions（打包版默认管理员，2026-10-24 用户拍板）、AGENTS（打包验证要点）
- 状态：已实现并冒烟通过，待用户双击验证 UAC
